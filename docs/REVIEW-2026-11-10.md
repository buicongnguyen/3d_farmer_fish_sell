# Willowmere review and rebuild plan (2026-11-10)

Four reviews in one: code, system, plan and design. Three read-only passes produced the findings: one read the code and the CI logs, one read every planning doc and compared it with `src/`, and one read the rules, ran `scripts/economy-sim.mjs`, built the game and took 22 screenshots on desktop and phone. Nothing in the game was changed.

## Verdict

**Do not rebuild from zero. Rebuild the game on top of what is good, in a fixed order.**

The world art, the rules layer in `game.mjs`, its 548 tests, the build and the performance system are worth keeping. What holds the game back is not missing features. It is that the core loop has no pacing, the story is a checklist, villagers do nothing, the HUD is a patchwork, and every new feature has gone into side systems. The agreed roadmap in `GAME-DIRECTION.md` already says most of this. None of its items has been started; the 47 commits after it went to disguises, rescue huts, VFX, jumping and birds.

## What to keep

- The toon village, the living pond and the warm writing voice.
- `act()` on plain state with deterministic tests, the economy simulator, three save profiles, English and Vietnamese.
- The shop rows, the honest prompt pill, the map panel, the eight town tales.
- The build's byte budget, hashed chunks, `keep-chunks` and the stale-chunk reload.
- The frame governor, instancing and shadow proxies.

## Findings

### Design (gameplay, story, UI)

| # | Problem | Evidence |
|---|---|---|
| 1 | The economy ends on day 5 | The simulator buys all 15 upgrades by day 5 and all 30 beds by day 2, then earns about 20,000 coins a day. All upgrades together cost 5,370. All 22 crops are on sale on day 1. |
| 2 | Days, seasons, energy and sleep mean nothing | Crops grow in 22 to 180 real seconds. `rest` gives +25 energy with no limit. The clock stops at 22:00 with no consequence. |
| 3 | The story is eight paragraphs with stat goals | `content.mjs:162-171`. No scenes, choices or stakes. June and Pip never act. The ending is a text note. |
| 4 | Villagers are scenery | One fixed line each (`game.mjs:132`). Any item is a +2 gift. Nothing reads hearts. |
| 5 | Two games with no bridge | The map shows "Chomper Swamp Lv 4" on day 1. No chapter mentions the wilds and the farm feeds nothing there. |
| 6 | Onboarding is one toast | It fades in 4.5 s. The real tutorial is a paragraph inside Help, and Help is hidden on phones. |
| 7 | Too many money sources, too few sinks | Run, patrol, shift, lessons, tale moments and the supper prize all pay daily. After upgrades only clothes and furniture cost anything. |
| 8 | The phone HUD fails the 11 px / 44 px standard | Top buttons 36 px, close 34 px, tabs 30 px, bar text 9.5 px. The Home button covers the quest tracker. The HUD takes about 40% of the screen. |
| 9 | Visible polish bugs | The title reads "Willowmere · game title™" (a leaked translation key, `language-view.mjs:12`). A grey default "Full screen" button. World labels bleed round the title card. 20 CSS files and about 40 font sizes. |
| 10 | Every action feels the same | One chime, one toast, one burst. Finishing a chapter is a toast. |

### Code and system

| # | Problem | Evidence |
|---|---|---|
| 1 | A save that fails to parse is overwritten within about 12 s | `load()` returns a fresh state on any error (`game.mjs:245`); autosave runs on the title screen (`main.mjs:436`); no backup (`profiles.mjs:9`). |
| 2 | Browser CI has been red for 20 nightly runs | About 45 of 64 suites fail: hard-coded Windows paths (`facility-talk-browser.mjs:6`), software-GL timeouts, and about 11 deterministic failures that look like real regressions. It does not gate the deploy. |
| 3 | One exception stops the game for good | The frame loop has no try/catch (`main.mjs:432-439`). |
| 4 | Features patch `World` at runtime | 25 modules write onto it; `update`, `click` and `nearest` are wrapped, so behaviour depends on install order. |
| 5 | Two god files | `main.mjs` (79 KB) and `world.mjs` (80 KB), in lines up to 2,895 characters, with 36 trailing `//` comments that can silently disable code. |
| 6 | 16 test files assert on source text | They pin formatting and block refactoring. |
| 7 | The save has no single schema | One hand-written migrator, settings whitelisted inline, sub-parsers in about 10 modules. |
| 8 | The first-frame budget has 458 bytes left | Combat, wilds and titans are still loaded up front through `minimap.mjs:31` and `main.mjs`. |
| 9 | Translation works by parsing English output back | Plus a whole-app `MutationObserver`. Any copy edit silently untranslates a string. |
| 10 | Smaller faults | `paused` has several owners; a missing `.catch` (`main.mjs:463`); game speed slows below 20 fps. |

### Plan and process

- `GAME-DIRECTION.md` names the right problems and the right order. Nothing on it has shipped.
- There are 29 docs and no single living plan. `README.md` still points at the first design plan; `RING9-REMAINING.md` says "not merged" for work that is merged; specs live outside the repo.
- Status docs record test counts and draw calls, not what a player experiences.
- No record of anyone playing a release on a real phone.

## The plan

Each phase ends with a playable, deployed game. No new combat, disguise, ring-world or VFX work until phase 4 is done.

### Phase 0: stop the bleeding (small)

1. Back up a save that fails to load and hold autosave until the player chooses.
2. Catch errors in the frame loop and show a message.
3. Add the missing `.catch`. (The governor item was dropped: step 3 already switches the shadow pass off at `world.mjs:602`; the review misread the table.)
4. Fix the title text, the "Full screen" button, the Home/tracker overlap and Help on phones.
5. Remove hard-coded paths from the browser suites; split them into deterministic suites that gate the deploy and timing suites that run nightly; triage the 11 deterministic failures.

### Phase 1: make the code safe to change (medium)

1. Format the code with Prettier; forbid trailing comments; replace the 16 source-text tests with behaviour tests.
2. Move creature data out of `wilds.mjs` so combat stops loading up front. This frees budget for everything below.
3. One save schema with versioned migrations and golden-file tests.
4. Split `main.mjs` into a panel registry, `hud`, `boot`, `loop` and touch controls.

### Phase 2: a core loop worth playing (large)

1. **Gate content by chapter.** Start with three crops. Each chapter unlocks one system with a celebration card. The wilds open in chapter 5 or 6, through the story.
2. **Give the day meaning.** Crops grow overnight, watering is daily, sleep is the commit point and ends with a day summary.
3. **Rebuild the economy.** An order board where named villagers ask for bundles, village projects funded in a fixed order, and late crops rescaled so a full farm earns about 1,500 a day. Tune it with the simulator.
4. **One daily jobs board** replaces doing every paid activity every day.
5. **Feed the wilds from the farm.** Cooked meals become food and buffs; materials from the wilds are needed for late upgrades and projects.

### Phase 3: story and characters (large)

1. Rewrite the eight chapters as short scenes with portraits and a through-line with stakes, a final choice and two endings.
2. Arcs for June and Pip: lines that react to yesterday, Pip grows up.
3. Eight key villagers with loved and disliked gifts and scenes at 2, 5 and 8 hearts, each paying off with a perk.
4. Six to ten rotating lines per villager, keyed to day, season, chapter and hearts.
5. Town tales become numbered side stories that each change something visible in the village.

### Phase 4: one UI (medium to large)

1. One token sheet: a five-step type scale, 11 px minimum, 44 px taps, one panel header. Fold 20 CSS files into tokens, HUD, panels and one file per feature.
2. A slim HUD: one top strip and one goal chip. On phones, one menu button that opens a tabbed hub.
3. A guided first ten minutes: Ada, plant, water, harvest, sell, sleep, with buttons appearing as they unlock.
4. Feedback with weight: coins fly to the purse, sounds differ by kind of action, a chapter ends on a full album page.
5. A title screen with a real logo, a slow camera pan and "Continue" as the main button.

### Phase 5: depth (later)

Real seasons with seasonal seeds and fish, a festival every seventh day, a collection book, scripted neighbours, the land grid, generations.

## Decisions for the owner

1. **Is the cosy village the main game, with the wilds as a later chapter?** The whole plan assumes yes, as `GAME-DIRECTION.md` already says.
2. **Overnight crops.** This changes how the game feels more than any other item. The alternative is to keep real-time growth and only slow it.
3. **Old saves.** The economy and gating changes cannot be applied cleanly to a late-game save. Either reset progress with a gift, or keep old saves in a "classic" profile.
4. **Who works on what.** Other sessions push to `main` every day. The plan needs one integration branch and a freeze on side features.
5. **This doc replaces the scattered plans.** If approved, the older status and handoff docs move to `docs/archive/`.

## Progress

**Phase 0, 2026-11-10.** Items 1 to 4 are done and checked in a browser on a phone-sized screen:

- An unreadable save is copied to its own key per profile before anything is saved over it, and Settings offers the copy as a download. If the copy cannot be written, saving pauses until the player presses Save now. Tests: `tests/save-backup.test.mjs`.
- A thrown error in the frame loop is logged and shown once; the game keeps drawing.
- The title reads "Willowmere" in English again; the Full screen button wears the game's button style; Settings has a "How to play" row, so phones can reach Help.
- The Home button no longer covers the quest tracker on portrait phones. The cause was the jump button's own CSS from October.
- Item 5 (browser suites as a deploy gate) is in progress on the branch `claude/ci-browser-gate`.

## How the claims were checked

- Read in code or logs: every row with a file reference, the CI history, the bundle size, the node test run.
- Measured by running: the economy simulation, the phone text and tap sizes, the screenshots.
- Judgement, not measurement: the comparison with other cosy games, the cost of the translation observer, whether the 11 deterministic CI failures are real regressions.
- Not checked: the roughly 270 KB of building dialogue was not read, combat was not played, landscape phone was not captured, and "not started" for roadmap items rests on names not found in `src/`.
